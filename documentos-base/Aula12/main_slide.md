## ...e replanejado à luz do ágil, por quê

Conteúdo e layout são as partes mais incertas do projeto — o cliente só sabe se gostou depois

de ver uma versão real, não uma descrição. Prometer o pacote fechado em 6 dias arrisca

entregar algo errado no fim do prazo.

Release 1 Release 2

A. Conteúdo

3d

Conteúdo C. Montar D. Publicar

+layout

OK 2d 1d

B. Layout

2d

O que muda, o que não muda

Caminho crítico e marcos não mudam. O que muda é o compromisso: Release 1

entrega uma versão validável com o cliente (conteúdo+layout); Release 2 fecha o

restante já ajustado pelo retorno dele.
